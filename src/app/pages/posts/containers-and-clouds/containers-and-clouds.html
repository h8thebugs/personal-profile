Containers and Clouds: A Beginner's Guide

There are lots of decent materials about the technical background of containerization. There are some good articles about how the cloud actually works. But (from what I can observe at least) there are no articles explaining why these two play so nice hand in hand from the technological point of view. All the major cloud platforms offer to manage your applications on Kubernetes, and most of their "out-of-the-box" services are also managed with it. In this post I will try to provide a collection of definitions that can be of use.

What is a Cloud?

To make it a lot easier to explain, let's start with a Virtual Machine. With a Virtual Machine, you can emulate a guest operating system that is different from the host operationg system. This can be useful for a number of reasons, here are some examples I can think of:

  • Try out different operating systems before directly installing it
  • Testing Android Applications directly on the developer's machine
  • Testing cross-platform applications on different target platforms
  • Use a software that was developed for a specific operating system that does not match the host operating system

Essentially you can run a different system on a part of the host machine's resources. You can even run multiple virtual machines on the host if that's your use-case e.g. all supported operating system of a cross platform applications. The software that does this is usually called hypervisor, and the process is called virtualization. It takes a part of the host's resource and runs isolated systems on it.

If in the case of classic VM's multiple machines can run on the same host, the Cloud Platforms do the opposite: multiple servers are combined into a single unified platform with the combined resources. This can even mean that the separate types of resources run in separate machines: specific servers for computing (CPU and RAM), specific servers for storage, specific servers with GPUs, etc.

This unified platform is mostly referred to as Hyperconverged Infrastructure (HCI). The main benefits of it is that it's easier to manage resources, you don't need to care at what exact server will your VM / container end up running, it enables the creation of specific servers for specific resources optimizing the infrastructure, makes the deployment process a lot more automated, and so on.

What is a Container?

A Container is a way to package your application with its dependencies to run in different environments. It is a middleground between a virtual machine and an application running directly on the host machine. Containers try to acheive a similar level of isolation as a full virtual machine while reducing some of the overhead. This is possible to achieve with two main kernel features (to keep things simple, I'm only referring to kernel features in linux, most servers are using linux anyway):

  • Process-level isolation with namespaces
  • Limiting resource usage with control groups

With the help of these features a container runtime (e.g. containerd) implements the management of these containers according to the OCI's specifications.

What is a Container on the Cloud?

Since containers are considerably smaller and more lightweight than VMs, they scale a lot better when you host multiple services, that's why Cloud Platforms started to integrate it on their platforms. Moreover, their possible drawbacks in terms of isolation are solved by the nature of Cloud infrastructures.

For managing the containers, the industry standard became to use Kubernetes, which is a tool to help in automated container orchestration at a large scale to implement infrastructure-related qualities like auto-scaling, high availability, resource usage monitoring, etc.

Microservices, microproblems, microsolutions

NOTE: The statements below are my observations and opinions.

Naturally, the flexibility of these kinds of infrastructures opened a lot of possibilities, an overwhelming number of technologies emerged aiming to solve really specific problems. The temptation to overcomplicate things became substantial, and a lot of applications became divided into microservices in a way that does not make sense anymore, which created a number of problems, which required to pull these solutions and integrate it into the already complex application.

We should remind ourselves from time to time that containers, cloud hosting and microservices are tools that should make the development and hosting of our application easier, simpler, cheaper, more flexible. If they don't serve their purpose, they are an impediment.
